## 每周必须完成
1. 对照上周真实打卡检查专业与英语进展，分别评估理解、实操、口语对话。
2. 生成两份独立的本周任务包（专业、英语），包含七天任务、完成标准和可执行证据。
3. 对专业课程提供“原理→代码/仿真→测试→故障解释”路径，不能仅用概念摘要代替。
4. 对英语课程提供“词块→语法→听力跟读→情景口语→再表达”路径，重点是问答交互，不是死背词表。
5. 每周至少 1 篇带真实过程的学习日志；如果尚无学习证据，就只发布“学习计划”而不发布“已学会”的假回顾。
6. 将每次调整写入 CHANGELOG 和对应周课程文章，不断积累知识薄弱点。

## 博客操作 SOP
1. 先识别真实 Hexo 项目根目录：须同时存在 `package.json`、`_config.yml`、`source/`、`themes/`（或被 npm 安装的主题）；查清实际 `deploy` 配置与 GitHub Pages 分支；不要假定 `hexo` 框架仓库是用户博客。
2. 备份博客、Git 分支、首页文件、主题配置；尽量在源码仓库变更，禁止直接覆盖已有文章和页面。
3. 若源码仓库已确认，把 `study-series/source/_posts/*.md` 导入文章源码，按 Solitude 主题当前配置增加“学习计划”菜单，提供专业与英语双入口；如无正确源码，只维护已发布站点独立静态页面与 MD 备份。
4. 对站点首页和博客导航做最小侵入修改，保留现有样式与旧文章；相同 URL 不重复生成、不破坏归档。
5. 发布前做 HTML 校验、路径检查、互链检查、移动端宽度检查、中文乱码检查、空白页面检查；构建时不得关闭安全检查。
6. 推送后核对 GitHub commit SHA 与 Pages 部署状态；若部署或前端验证未完成，准确报告限制，不说“全部成功”。
7. 不发布 API 密钥、密码、内部项目细节、公司保密代码；技术实机相关任务必须确认硬件安全与人工监督。

## 迭代规则
- 基于实际完成度调整 1–2 周的任务，12 周总纲只在有证据时修订。
- 完成率 <60%：减负、减少新知识；60–85%：正常推进并补薄弱点；>85% 且测验通过：提高难度。
- 对每篇新文章至少有目标、先验基础、分天任务、验收、复盘、参考材料。
- 每次对外发布必须保留原文章 URL，避免死链；版本提交信息清晰，能回滚。
- 不要为了增加更新频率凭空捏造学习成果。计划文档公开、真实作业与私人笔记分层管理。
