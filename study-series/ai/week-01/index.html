本周只解决一个问题

AI 是否能帮嵌入式开发者在代码提交前发现一个明确的边界错误？本周不安装复杂 RAG、不搭多 Agent、不接真实 SVN 服务器。

样例 C 代码

#include <stdint.h>
uint16_t clamp_duty(int32_t duty) {
    if (duty > 1000) return 1000;
    return (uint16_t)duty;
}

预期规则：合法占空比区间为 0–1000。负输入本应被饱和到 0，但上述代码将负数转换为 uint16_t，因而可能出现错误的大数。

可直接给模型的提示词

你是只读的嵌入式 C 代码审查器。只报告能标注具体函数、触发条件和工程影响的问题，不要修改代码或调用硬件。输出字段：severity、symbol、trigger、impact、evidence、suggested_test、confidence。若存在不确定性，明确说明。规则：返回的 duty 必须在 0..1000 之间；负值需被限制为 0。
