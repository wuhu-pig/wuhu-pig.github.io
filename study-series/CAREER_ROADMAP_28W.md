# 28 周职业能力成长路线图（正式执行版）
> 生效时间：2026-10-12。基准完成日：2027-04-25。原 12 周双轨课程保留为知识库与教学资料，**不再作为每天 75 分钟的进度承诺**。

## 1. 长期目标
**主职业定位**：基于 NXP/Infineon 等 MCU 的嵌入式电机控制研发工程师，能够独立分析控制算法、实时性和测试问题。
**技术增益**：以 AI 辅助代码审查、需求分析、单测生成、问题检索、FreeMASTER 波形分析提高可靠研发效率，先能验证 ROI 再增加 Agent/RAG/MCP。
**职业英语**：简单句出发，提高英语口语持续表达、会议问答和技术面试能力。暂以 A2→B1 难度训练，不是等级认证。

## 2. 时间预算（一个自然周）
- 周一/三/五视为**示例健身日**，每次 15 分钟英语；实际健身日可互换。
- 周二：技术 40m + AI 20m；周四：技术 35m + AI 25m。
- 周六：技术 65m + AI 35m + 英语 20m。
- 周日：技术 25m + AI 55m + 英语 40m。
- 周合计：技术 165m + AI 135m + 英语 105m = **405 分钟 = 6h45m**。
- 工作日累计 165 分钟（2h45），周末各 120 分钟。**周末可按疲劳度减少，总量下调至 4–5h。**
- 健身日晚间到家较晚，不安排编码、大模型部署、重推导，也不牺牲 23:30 睡觉时间。
- 可选碎片英语听力不计入强制工时。实际累积进度以提交成果而非签到时长计算。

### AI Week 01：第一个有价值的小实验
**业务问题：** AI 能否帮我在提交前发现 C 代码越界/类型转换类缺陷，而不是泛泛给代码建议？
**安全边界：** 不上传工作代码、内部需求或客户信息；从完全合成的 C 函数和 diff 开始。

```c
#include <stdint.h>
uint16_t clamp_duty(int32_t duty) {
    if (duty > 1000) return 1000;
    return (uint16_t)duty;
}
```

**已知缺陷**：负数 duty 被转换成无符号 16 位值，`clamp_duty(-1)` 返回 65535，而非预期 0。预期测试：`-1→0`, `500→500`, `1200→1000`。
这是**合成软件测试案例**，不能把它直接复制到真实功率驱动系统。

**给 AI 的任务契约**：
```
角色：只读嵌入式 C 代码审查器。
仅报告能够指出具体语句、触发条件和潜在影响的问题。
禁止修改文件、调用硬件、推断不存在的需求。
输出以下字段：
severity, file, line_or_symbol, condition, impact, evidence, suggested_test, confidence
无法确认的事项放入 uncertainties，不得编造证据。
审查标准：uint16_t duty 应在 0..1000 之间，超界需要饱和。
```
**人工验证**：检查模型是否识别负值转换，是否写出触发条件与可复现测试，是否产生无证据的额外结论；记录审查耗时（含人工核查）。没有足够样本时不宣称准确率。

## 6. AI 技能每四周验收（不可跳过）
每个 AI 工具的结论必须形成 **输入样本 → 预期结果 → AI 实际输出 → 人工判定 → 回归用例 → 时间成本**。先用 3 个样例打通流程，再扩展到至少 10–20 条独立样例。评估项：真实问题找回、错误告警、无证据输出、重复运行一致性、人工复核时间、是否触碰隐私边界。效果不达标则优化流程或停止投入。

## 7. 周末复盘和调整
- 完成率少于 60%：下周只留本周未完成的 P0，不追加新知识。
- 60–85%：继续原计划，专门补一个最弱项。
- 超过 85% 且小测通过：提高代码复杂度或英文追问，不增加上课时长。
- 缺少证据只能标记“未知”，不可替用户勾选完成。
- 周末休息应当是计划的一部分；连续睡眠不足时自动启用轻量模式。
